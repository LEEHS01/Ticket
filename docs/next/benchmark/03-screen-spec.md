# 03. 미리내 마당 화면 설계안

UI 세션이 이 문서만 보고 화면을 만들 수 있게 치수와 규격을 숫자로 적는다. 근거는 [01](01-services.md)·[02](02-design-basis.md).
단위는 CSS px. `PC`는 1280px 이상, `모바일`은 767px 이하를 말한다(4장 중단점). 인라인 `style` 속성은 지금처럼 쓰지 않는다(CSP).

---

## 0. 핵심 결정 (요약)

1. **서비스 뼈대를 실제 서비스 관례대로**: 3단 머리글(보조 링크 32 + 로고·검색 72 + 장르 메뉴 52 고정), 모바일 하단 탭 막대 56, 정책·고객센터가 있는 푸터, 보조 화면(랭킹·티켓 오픈·검색·공지·이용안내) 추가.
2. **메인 첫 화면은 큰 배너**: 본문 폭 1200 안에 1200×400(3:1) 슬라이드. 모바일은 포스터로 만든 335×400 카드(새 이미지 불필요).
3. **정돈된 격자와 높은 밀도**: 본문 1200px, 목록 5열 고정(필터 있으면 4열), 포스터 3:4 유지, 카드마다 상태 머리표(D-n·매진 임박·매진·판매 종료·순위).
4. **장식을 걷어 낸 시각 기준**: 흰 바탕, 글꼴 Pretendard 하나, 회색 4단계, 행동 색 1개(새 청록 `#0A7C78`), 경고 빨강 1개. 장식 글꼴·종이 바탕·핑크 강조를 없앤다.
5. **상세는 오른쪽 고정 예매 상자(PC) / 하단 고정 예매 막대 + 하단 판(모바일)**, 상세 본문은 탭으로 나눈다.
6. **예매 흐름은 "좌석 → 예매 확인·결제 → 완료" 3단계 표시**. 예매 확인 화면 안에 **모의 결제 수단 선택**(카드 번호 입력 없음)을 넣는다(5장, 결정 필요).

## 2. 공통 틀

### 2.1 중단점과 본문 폭
| 이름 | 화면 폭 | 본문 폭 | 좌우 여백 | 포스터 목록 열 | 열 간격 / 행 간격 |
|---|---|---|---|---|---|
| `sm` | 0–767 | 100% | 20 | 2 | 12 / 32 |
| `md` | 768–1023 | 100% | 24 | 3 | 20 / 36 |
| `lg` | 1024–1279 | 100% | 32 | 4 | 24 / 40 |
| `xl` | 1280 이상 | **1200 고정, 가운데** | (자동) | **5** | 24 / 40 |

- `xl`에서 5열 카드 폭 = (1200 − 24×4) / 5 = **220.8**, 포스터 220.8 × 294.4(3:4).
- 가로로 넘기는 카드 줄(모바일 섹션)은 카드 폭 **140**, 간격 12, 첫 카드 왼쪽 20(스크롤 영역이 화면 끝까지 닿고 안쪽 여백으로 시작).

### 2.2 PC 머리글 (높이 합 156, 스크롤 후 52만 남음)
```
y0   ┌ 보조 링크 줄 32 (흰 바탕, 아래 1px #E3E6EA) ───────────── 로그인 · 회원가입 · 내 예매 · 고객센터 ┐  12/400 #4B5260, 링크 사이 세로선 1×10
y32  ├ 로고·검색 줄 72 ─────────────────────────────────────────────────────────────────────────┤
     │ [미리내 마당] (글자 로고 높이 28)   [🔍 공연, 공연장 검색 …………………… 460×44]        (🎫)(👤)  │
y104 ├ 장르 메뉴 줄 52 (position: sticky; top: 0; 흰 바탕; 아래 1px #E3E6EA) ───────────────────┤
     │ 홈  콘서트  뮤지컬  연극  클래식  │  랭킹  티켓 오픈  공지사항                                 │  16/600 #4B5260, 사이 32
     │ ━━  ← 선택: 글자 #16191D + 아래 3px #0A7C78 막대(글자 폭)                                       │
y156 └─────────────────────────────────────────────────────────────────────────────────────────┘
```
- 검색창: 460×44, 모서리 22(완전 둥금), 바탕 `#F5F6F8`, 테두리 없음, 왼쪽 돋보기 20, 안쪽 여백 16, 글자 15. 포커스 시 흰 바탕 + 1.5px `#0A7C78` 테두리.
  - 포커스하면 아래로 펼침 상자(460, 모서리 12, 그림자 `--shadow-float`): `최근 검색어`(localStorage, 최대 8개, 하나씩 지우기) / `많이 찾는 공연`(랭킹 1~5위 제목). 엔터 → `/search?q=`.
- 아이콘 단추: 44×44, 아이콘 24, 아래 11px 글자(`내 예매`, `마이`/`로그인`).
- 스크롤하면 장르 메뉴 줄만 위에 붙는다. 붙은 상태에서는 왼쪽에 작은 로고(18px)가 나타난다(투명도 전환 150ms).

### 2.3 모바일 머리글과 하단 탭 막대
```
┌ 머리글 56 (sticky, 흰 바탕, 아래 1px) ┐
│ [미리내 마당]               (🔍)      │ 로고 높이 22, 아이콘 단추 44
├ 칩 줄 48 (메인·장르만, 같이 sticky) ─┤
│ (전체)(콘서트)(뮤지컬)(연극)(클래식)   │ 칩 32, 사이 8, 가로 스크롤
└──────────────────────────────────────┘
...
┌ 하단 탭 막대 56 + safe-area (fixed, 흰 바탕, 위 1px) ┐
│  ⌂     ♛      ⏰       🎫       👤                   │ 아이콘 24, 글자 11/500
│ 홈   랭킹  티켓 오픈  내 예매   마이                   │ 선택 #16191D, 나머지 #666D79
└──────────────────────────────────────────────────────┘
```
- 하단 탭 막대는 **공연 상세(고정 예매 막대로 바뀜)·예매 단계·로그인/가입에서 숨긴다**.
- 상세·하위 화면의 모바일 머리글: `←`(뒤로) / 가운데 제목(17/600, 스크롤 120px 지나면 나타남) / 오른쪽 `링크 복사` 아이콘.

### 2.4 예매 단계 머리글 (대기·좌석·확인, PC와 모바일 공통)
```
PC  ┌ 64 ───────────────────────────────────────────────────────────────────┐
    │ [미리내 마당]     ① 좌석 선택 ── ② 예매 확인·결제 ── ③ 예매 완료      [예매 그만두기] │
    └───────────────────────────────────────────────────────────────────────┘
모바일 ┌ 56 ───────────────────────────────┐
      │ ✕   좌석 선택 (17/600)    08:41 ⏱ │  ← 남은 시간(있을 때), 1분 미만이면 빨강
      │ ▬▬▬▬▬▬▬▬▬▬▬░░░░░░░░░░░░ (진행 막대 3px) │
      └───────────────────────────────────┘
```
- 단계 표시: 원 24(번호 13/700), 현재 단계 원 `#0A7C78` 흰 숫자 + 글자 15/700 `#16191D`, 지난 단계 원 `#CDEBE9` 체크, 다음 단계 원 테두리 `#CDD2D9` 글자 `#666D79`. 단계 사이 선 32×1.
- 대기 화면은 번호 없는 "입장 대기" 상태로 표시하고 ①은 아직 회색.
- `예매 그만두기`/`✕`: 확인 대화상자 후 선점·대기 해제(`DELETE /api/queue`) → 상세로.

## 3. 디자인 기준

### 3.1 색 토큰

브랜드 색은 **청록 `#0A7C78`**("미리내 = 은하수"가 걸린 밤하늘의 청록빛).
참고한 서비스의 행동 색 — NOL 파랑(`#4154FF` 근처), 예스24 주황·빨강(`#EC7D2C`·`#ED4037` 근처), 멜론 밝은 녹색, 티켓링크 빨강 계열 — 과 색상(hue)·명도가 모두 떨어진다. 지금 쓰는 리소 블루(`#2F4FD8`)는 NOL 파랑과 같은 계열이라 버린다.

### 3.5 움직임
- 기본 전환 150~200ms `ease-out`. 하단 판 열림 240ms, 닫힘 200ms.
- 배너 자동 넘김 5초, 마우스 올림·포커스·화면 밖이면 멈춤, `prefers-reduced-motion: reduce`면 자동 넘김 끔.
- 뼈대(스켈레톤)는 깜빡임 없이 고정 색(`--c-bg-sub2`). 움직이는 반짝임 효과 쓰지 않음.

## 5. 예매 흐름: 실제 서비스와 비교

| 단계 | 실제 서비스(일반 구성, 예매 창 안쪽은 **직접 보지 못함**) | 미리내 마당 지금 | 새 설계 |
|---|---|---|---|
| 1 | 상세에서 관람일·회차 선택(NOL: 오른쪽 고정 상자 ✅ / 예스24·멜론: 본문 아래 상자 ✅) | 상세 3단 격자의 한 칸 | 오른쪽 고정 예매 상자(PC), 하단 판(모바일) |
| 2 | 인기 공연이면 대기열 | 대기 화면(로그인 필요) | 같음, 예매 단계 머리글 + 대기 상자 |
| 3 | 예매 창: 좌석 선택(남은 시간 표시 시작) | 좌석 화면 | `① 좌석 선택`, 오른쪽 선택 상자, 모바일 하단 판 |
| 4 | 가격·할인(권종) 선택 | 없음 | **넣지 않음**(쿠폰·할인은 범위 밖). 등급 가격 그대로 |
| 5 | 배송·수령 방법 + 예매자 확인 | 예매 확인(계정 정보) | `② 예매 확인·결제` 안의 ②예매자 정보 ③티켓 수령(모바일 티켓 하나) |
| 6 | 결제(카드사·간편결제 창) | 없음(확정으로 대체) | `② 예매 확인·결제` 안의 ④**모의 결제 수단** + ⑤동의 |
| 7 | 완료 | 완료 | `③ 예매 완료` |

단계 표시는 실제 서비스의 5단계를 그대로 흉내 내지 않고, 우리에게 실제로 있는 화면 수(좌석 → 확인·결제 → 완료 = 3)만 번호를 붙인다. 회차 선택은 상세에서 끝나고, 대기는 번호 없는 사전 단계로 보인다.

### 5.1 모의 결제 수단 화면을 넣을지 — 의견: **넣는다, 단 "예매 확인 화면 안의 섹션"으로, 결제 정보 입력 없이**
근거:
- 네 서비스 모두 예매 흐름의 끝은 "결제 수단 선택 → 결제" 장면이다. 결제 장면이 없으면 흐름이 "좌석 → 확인 → 끝"으로 짧아 시제품처럼 보인다(02 문서 4장 9번과 같은 이유).
- 별도 단계(화면)로 만들면 선점 남은 시간 안에 화면이 하나 늘고, 서버에는 의미 없는 왕복이 생긴다. 확인 화면 안 섹션이면 화면 수는 그대로다.
- **카드 번호·유효기간 같은 입력칸은 만들지 않는다.** 가짜라도 결제 정보 입력 화면은 실제 결제 화면처럼 보여 오해를 부르고, 사용자가 실제 카드 번호를 넣을 위험이 있다. 수단 이름만 고르는 라디오 카드 + "실습용 모의 결제" 머리표 + "결제 정보는 받지 않아요" 문장으로 충분하다.
- 백엔드는 고른 수단 문자열만 예매에 기록하면 된다(6장 `paymentMethod`). 결제 대행 연동·환불 처리 같은 상태는 생기지 않는다(DB 하나만 복제하면 된다는 원칙 유지).
- 넣지 않는 경우의 대안: ④를 빼고 버튼을 `예매 완료`로(4.9 끝).

## 6. 새 화면에 필요한데 지금 API(v3)에 없는 데이터

조율 세션이 계약 v4를 정할 때 쓰도록 정리했다. **필수** = 이 설계의 화면이 그 데이터 없이는 성립하지 않음, **있으면 좋음** = 없으면 그 요소를 숨기거나 프론트 계산·정적 데이터로 대신함.

| # | 데이터 | 쓰는 화면 | 필요 | 제안 형태 | 없을 때 |
|---|---|---|---|---|---|
| 1 | **메인 배너 목록**(순서, 공연, 문구, 그림) | 메인 배너 | **필수** | `GET /api/banners` → `{ banners: [{ id, showId, eyebrow(장르 등 짧은 말), title, subtitle, imageUrl(PC 3:1), mobileImageUrl?, startsAt, endsAt }] }`, 노출 기간 안의 것만, 순서대로 최대 6개. 그림 파일은 프론트 `public/banners/`에 두고 `imageUrl`은 경로 | 프론트 정적 설정(공연 id 목록 + 문구)으로 대신할 수 있음 — 조율 세션 판단 |
| 2 | **공지사항** | 공지 목록·상세, 메인 공지 띠 | **필수**(공지 화면을 넣는다면) | `GET /api/notices?category=&page=` → `{ notices: [{ id, category: "TICKET_OPEN"\|"SERVICE", title, pinned, publishedAt, ticketOpenAt?, showId? }], page, totalPages }`, `GET /api/notices/:id` → 위 + `body`(일반 텍스트). 시드: 오픈 예정 공연마다 티켓 오픈 공지 1건 + 서비스 안내 3건 | 공지 화면·띠를 뺌 |
| 3 | **모의 결제 수단** | 예매 확인·결제, 완료, 내 예매 | **필수**(모의 결제를 넣는다면) | `POST /api/reservations` 본문에 `paymentMethod: "CARD"\|"EASY_PAY"\|"BANK_TRANSFER"`(선택, 기본 `CARD`), `Reservation`에 `paymentMethod` 추가 | 결제 섹션을 뺌(4.9) |

| 7 | 랭킹 기준 시각·예매 점유율·순위 변동·기간 | 랭킹 화면 | 있으면 좋음 | `GET /api/rankings?genre=&period=DAILY\|WEEKLY` → `{ rankedAt, items: [{ show: ShowSummary, rank, share(%), change: number\|"NEW" }] }` | 지금 `rank`로 순위만, 기간 단추·점유율·변동 숨김 |

| 13 | 관심 공연(찜) | 상세 ♡, 마이 | 나중 | 새 테이블 + `POST/DELETE /api/me/wishlist/:showId` | 넣지 않음(자리도 두지 않음) |

프론트에서 계산하므로 **API가 필요 없는 것**: D-day, 매진 임박(잔여 < 15%), 이번 주 공연, 오픈 예정 목록(`status=UPCOMING`, `sort=opening`), 검색 필터·정렬(공연 18개), 최근 검색어(localStorage), `.ics` 캘린더 파일, 취소 가능 기한(=회차 시작 전), FAQ·이용안내·정책 문서(정적).

## 7. UI 세션에 넘길 구현 메모

- 토큰은 `styles.css` 맨 위 `:root`에 이 문서의 이름 그대로 둔다(`--c-*`, `--t-*`는 `font` 축약 대신 크기·굵기·줄 높이 세 변수로 나눠도 됨, `--s-*`, `--r-*`, `--shadow-*`).
- 글꼴: `@fontsource/ibm-plex-sans-kr`, `@fontsource/black-han-sans`를 빼고 `pretendard`(가변·다이내믹 서브셋 CSS)를 넣는다. OFL 라이선스 파일을 `public/licenses/`에.
- 이미지 경로(04 문서와 같은 이름): 배너 `public/banners/banner-{showId}.webp`(2400×800) + `-sm.webp`(1200×400), 그림 `public/illust/*.webp`, 포스터는 지금 그대로 `public/posters/{id}.webp`, `{id}-sm.webp`.
- 이미지 목록은 지금 포스터처럼 빌드 시점 목록(가상 모듈)로 알고, 없으면 3.7 대체 표시.
- 접근성: 지금 구현의 장점(건너뛰기 링크, 화면 전환 시 h1 포커스, 좌석 키보드 이동, aria-live 남은 시간)을 유지한다. 배너는 `aria-roledescription="슬라이드"`, 일시정지 단추 필수.
