# 01. 실제 예매 서비스 분석

조사일: 2026-11-24. 도구: 데스크톱 앱 내장 브라우저. PC는 뷰포트 1440×900, 모바일은 375×812(모바일 기기 흉내).
치수는 페이지 안에서 `getBoundingClientRect`/`getComputedStyle`을 읽는 스크립트로 잰 값이다(읽기 전용. 페이지의 내부 API는 부르지 않았다).
캡처는 `.ref/benchmark/`(git 제외)에만 있다. 이 문서에는 글과 배치도만 둔다.

지킨 선: 로그인 안 함, 예매하기 버튼 안 누름, 좌석 안 누름, 자동 반복 요청 없음. 광고 팝업은 "닫기"만 눌렀다.
NOL 검색 화면을 보려고 검색창에 장르 이름 한 단어를 넣어 검색한 것이 유일한 입력이다.

표기: ✅ 직접 보고 잼 · 🔶 직접 봤지만 일부만 잼 · ❌ 못 봄(이유 적음)

## 1. 티켓링크

### 1.1 상태
- PC `www.ticketlink.co.kr/home`: 글은 다 읽혔지만 페이지가 3~5초마다 다시 불러와져서 측정 스크립트가 매번 끊겼다. `/performance/16`(장르) 같은 다른 PC 주소도 홈으로 되돌아갔다. 자동화 감지로 보이며, 우회하지 않고 멈췄다.
- 모바일 `m.ticketlink.co.kr`: 정상. 메인과 티켓 오픈 목록을 쟀다.

### 1.2 PC 메인 🔶 (글 구조만, 치수 없음)
위에서 아래 순서:
1. 머리글: 맨 위 얇은 띠(언어 선택 / 로그인·예매확인·회원가입·고객센터 같은 보조 링크) → 로고 + 대분류 탭 2개(공연·전시 / 스포츠) + 검색창.
2. 메인 배너: 슬라이드 20장, 점 페이지 표시.
3. **티켓 오픈**: 글 목록 5줄. 한 줄 = [단독판매] 같은 머리표 + 공연명 + "오픈 안내", 오른쪽에 `11.25(수) 20:00`.
4. **랭킹**: "장르별 / 지역별" 전환 + 장르 탭 7개 + 기간 탭(일간·주간·월간·연간) + 1~5위(포스터, 순위 숫자 + "위", 공연명, 기간 `2026.08.13 - 2027.03.01`).
5. 오늘의 추천: 큰 배너 슬라이드 + 아래 작은 썸네일 목록(썸네일로 배너를 바꿈).
6. 제휴 할인 카드: 할인율 %, 정가(취소선), 할인가.
7. 기획전 슬라이드, 영상(TICKET SPOT) 슬라이드.
8. 이주의 공연·전시(포스터 + 기간).
9. 베스트 공연·전시: 공연명 / 공연장 / 기간 3줄 카드.
10. 공연장 탭(운영 공연장별 목록).

- 문서 높이 약 3,870px(모바일 메인이 PC보다 짧고 단순하다).

### 1.4 모바일 티켓 오픈 ✅
- 맨 위 큰 카드(220×294 포스터) 슬라이드 → 오픈 목록(190×254 포스터 카드 16개, 그 아래 108×146 목록).
- 한 줄 = 오픈 일시(`2026.11.25 11:00 오픈`) + 공연명 + **알림 받기** 버튼.

### 1.5 못 본 것 ❌
PC 상세·장르·검색·랭킹·공지(자동화 감지로 홈으로 되돌아감), 모바일 상세(상품 링크가 스크립트 클릭이라 주소를 못 얻음). 로그인·좌석·결제·마이페이지(규칙상 안 봄).

## 2. NOL 티켓 (야놀자, 옛 인터파크 티켓)

`tickets.interpark.com` → `nol.yanolja.com/ticket`으로 이동한다. 여행 플랫폼 안의 "티켓" 탭 구조라서 머리글이 여행·숙소와 공유된다.

### 2.1 공통 치수 (PC) ✅
| 항목 | 값 |
|---|---|
| 머리글 | **고정(fixed) 72px**. 로고 + 큰 검색창(둥근 알약형) + 오른쪽 아이콘 4개(마이·찜·장바구니·최근 본) |
| 둘째 줄 메뉴 | 전체 카테고리(햄버거) / 홈 / **티켓**(선택, 파란 밑줄) / 특가 / 쿠폰·혜택 / … |
| 본문 폭 | 1240px(1440 화면에서 좌우 92px) |
| 글꼴 | Pretendard, 본문 글자색 `#1B1C1F` 근처, 보조 `#6E6F73`, 흐린 `#8B8D92` |
| 행동 색 | 파랑 1개(예매하기 버튼, 선택 날짜, 오픈 시각 글자) |
| 경고 색 | 빨강 1개(할인율, 일요일, 혜택 수치) |
| 면 색 | 흰 바탕 + 아주 옅은 회색 면 `#F2F3F7`, `#F7F8FB` |
| 글자 크기 빈도 | 18/600(카드 제목)이 가장 많고, 14/400(보조), 16/400, 12/700·11/700(머리표), 24/700(섹션 제목) |
| 모서리 | 버튼 16px, 칩 완전 둥금(9999px) |

## 7. 로그인해 주면 더 볼 가치가 있는 화면

규칙상 이번에는 보지 않았다. 아래는 일반적으로 알려진 구성이며 **직접 보지 못함**이다. 사용자가 직접 로그인해 준다면 우선순위 순으로:

1. **예매 창의 단계 구성(NOL 또는 예스24)** — 회차 선택 후 뜨는 예매 창의 단계 표시(관람일/회차 → 좌석 → 가격/할인 → 배송/예매자 확인 → 결제), 남은 시간 표시 위치, 좌석 배치도의 범례와 확대/축소 방식. 우리 좌석·확인 화면 설계에 가장 직접 쓰인다. (좌석은 누르지 않고 화면만 보는 조건)
2. **대기열 화면** — 인기 공연 오픈 시각에만 뜬다. 대기 순번·예상 시간·진행 막대 배치.
3. **마이페이지 예매 내역** — 예매 목록 카드 구성, 취소 가능 기한 표시, 취소 수수료 안내 방식.
4. 로그인 화면(NOL·멜론) — 겉모습 비교용. 우선순위 낮음.

일반적으로 알려진 예매 창 구성(직접 보지 못함):
```
[관람일/회차] → [좌석 선택] → [가격/할인 선택] → [배송/수령 방법 + 예매자 정보] → [결제] → 완료
  · 예매 창은 별도 팝업(PC)이나 전체 화면(모바일)
  · 좌석 단계부터 남은 시간(예: 7~10분)이 보임
  · 오른쪽에 "선택 내역" 상자(공연명·일시·좌석·금액)가 단계 내내 고정
```
