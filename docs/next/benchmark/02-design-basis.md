# 02. 디자인 근거

목표: 지금 화면이 "AI가 만든 시제품"처럼 보이는 이유를 실제 서비스와 대조해 짚고, 새 화면의 기준을 근거와 함께 정한다.
관찰 수치의 출처는 [01-services.md](01-services.md)다.

## 1. 국내 커머스·예매 화면의 공통 관례

네 서비스(티켓링크·NOL·예스24·멜론)에서 2곳 이상 겹친 것만 적는다.

### 1.1 글꼴과 글자 크기
| 관례 | 관찰 | 우리 기준으로 옮기면 |
|---|---|---|
| 본문 글꼴은 고딕 하나 | NOL·티켓링크·예스24 모바일이 Pretendard. 예스24 PC는 나눔바른고딕, 멜론은 시스템 고딕 | 글꼴 1종(Pretendard). 장식용 제목 글꼴 없음 |
| 본문 14~16px | NOL 카드 제목 18/600, 보조 14/400. 예스24 13~16. 멜론 12~14(오래된 화면) | 본문 15px, 보조 13~14px, 카드 제목 16px |
| 굵기는 400·600·700 세 가지 | NOL: 400/600/700, 예스24: 300/400/700 | 400(본문), 600(카드 제목·탭), 700(섹션 제목·가격 강조) |
| 섹션 제목은 18~24px | NOL PC 24/700, 모바일 18/700, 티켓링크 모바일 20/700 | PC 22/700, 모바일 18/700 |
| 상세 공연명은 22~35px | NOL 22/700, 멜론 26, 예스24 35 | PC 28/700, 모바일 20/700 |
| 순위 숫자는 크고 굵게 | NOL 32/700, 티켓링크 모바일 40/700, 예스24 모바일 35/800 | PC 32/800, 모바일 28/800 (숫자 글꼴은 본문과 같은 Pretendard, 고정폭 숫자) |

### 1.2 색 사용량
| 관례 | 관찰 |
|---|---|
| 바탕은 흰색 | 네 곳 모두 흰 바탕. 회색 면은 공지 띠·필터 상자·푸터 위 묶음에만(NOL `#F2F3F7`, `#F7F8FB`) |
| 글자는 회색 3~4단계 | 예스24 `#333/#666/#999`, NOL `#1B1C1F/#6E6F73/#8B8D92`, 멜론 `#333/#666/#888` |
| 행동 색은 1개 | NOL 파랑, 예스24 주황·빨강, 멜론 녹색. 예매하기 버튼·선택 상태·오픈 시각에만 |
| 빨강은 "가격·할인·일요일·경고" 전용 | 네 곳 모두. 브랜드 색과 별개로 쓰는 관례적 경고 색 |
| 색이 많은 곳은 포스터뿐 | 화면 장식 색 거의 없음. 색은 포스터와 배너 이미지가 가져간다 |

### 1.3 표기
| 항목 | 관례 | 우리 표기 |
|---|---|---|
| 가격 | `154,000원` (쉼표 + 원) | 그대로. 목록은 `55,000원~`, 상세는 등급별 전부 |
| 기간 | `2026.12.03 ~ 2027.02.21` | 그대로. 같은 해면 `2026.12.03 ~ 12.21` |
| 오픈 일시 | `11.25(수) 20:00`, 가까우면 `오늘 14:00`·`내일 11:00` | 그대로 |
| D-day | `D-3`, `D-1`, 당일은 `D-DAY` 또는 `Today` | `D-3`, `D-1`, `오늘 오픈` |
| 회차 | `1회 19:30`, `오후 6시 00분` | `1회 19:30` (24시간제) |
| 남은 좌석 | NOL 회차 카드 `VIP석 61 · R석 50` | `VIP석 12석` / `매진` |
| 요일 | 일요일·공휴일 빨강, 토요일은 서비스마다 다름(파랑 또는 검정) | 일요일 빨강, 토요일 기본 글자색 |

### 1.4 크기·밀도
| 항목 | 관찰 | 우리 기준 |
|---|---|---|
| 본문 최대 폭 | 1200(예스24) · 1240(NOL) · 1008(멜론) | **1200px** |
| PC 목록 열 수 | 5열이 기본(랭킹·오픈), 필터가 있으면 4열 | 5열, 필터 있는 검색은 4열 |
| 포스터 비율 | 3:4(NOL·티켓링크), 5:7(예스24·멜론) | **3:4 유지**(기존 포스터 그대로) |
| 버튼 높이 | 예매하기 52(NOL)·49(멜론)·60(예스24), 로그인 59(예스24) | 큰 버튼 52, 보통 44, 작은 버튼 36 |
| 칩 | 36px, 완전 둥금(NOL) | 36px(PC)/32px(모바일), 완전 둥금 |
| 모바일 좌우 여백 | 15~20px | 20px |
| 모바일 하단 | 탭 막대 55~57px, 상세는 고정 예매 버튼 막대 | 탭 막대 56px, 상세 고정 막대 76px(버튼 52 + 위아래 12) |
| 섹션 간격 | NOL PC 섹션 하나 500~850px, 제목과 내용 사이 약 24~32px | 섹션 사이 64px(PC)/40px(모바일), 제목 아래 20px |
| 한 화면 정보량 | NOL 메인 PC 문서 높이 약 4,600px, 섹션 6개 | 메인 6~7개 섹션 |

### 1.5 터치·접근성 기준 (공개 표준)
- WCAG 2.2 성공 기준 2.5.8(AA): 누르는 대상은 최소 24×24 CSS px(간격 예외 있음). 2.5.5(AAA)는 44×44.
  → 우리는 버튼·칩 최소 32px 높이, 모바일 주요 버튼 44px 이상, 달력 날짜 칸 40px 이상.
- 글자 대비 4.5:1 이상(본문), 큰 글자 3:1 이상. 색 토큰은 이 기준으로 골랐다(03 문서 3.1).

## 2. 무료 한글 글꼴 후보와 라이선스

웹 번들에 넣어 배포하는 경우(우리 프론트는 `@fontsource`처럼 npm 패키지로 번들한다)를 기준으로 본다.

| 글꼴 | 라이선스 | 번들 배포 | 장점 | 단점 | 판단 |
|---|---|---|---|---|---|
| **Pretendard** | SIL OFL 1.1 (예약 글꼴 이름 "Pretendard") | 가능. 상업 사용·수정·재배포 허용, 글꼴 단독 판매만 금지 | 국내 예매 서비스 다수가 쓰는 사실상 표준. 9가지 굵기, 가변 글꼴, 한글 하위 집합(다이내믹 서브셋) 제공. 정부 디자인 시스템(KRDS)의 기본 글꼴도 이 계열(Pretendard GOV) | 흔하다(그래서 "서비스처럼" 보인다) | **채택(본문·UI 전부)** |
| SUIT | SIL OFL | 가능 | 9가지 굵기, 가변 글꼴. Pretendard보다 살짝 둥글고 단단함 | 사용처가 적어 숫자·영문 품질 검증이 덜 됨 | 대안 1순위 |
| Wanted Sans | SIL OFL 1.1 | 가능(단독 판매·라이선스 변경 금지) | 원티드가 공개한 브랜드 글꼴, 굵은 굵기의 표정이 좋음 | 특정 회사 브랜드 글꼴로 인식될 수 있음 | 로고에도 쓰지 않음 |
| IBM Plex Sans KR (지금 씀) | SIL OFL | 가능 | 품질 좋음 | 국내 커머스에서 거의 안 씀 → "개발 문서" 느낌 | 교체 |
| Black Han Sans (지금 씀, 제목용) | SIL OFL | 가능 | 강한 표정 | 굵은 장식 글꼴을 큰 크기로 쓰는 것이 "AI 데모" 인상의 큰 원인(3장) | **제거** |
| Noto Sans KR | SIL OFL | 가능 | 안정적 | Pretendard보다 자간·숫자가 덜 다듬어짐, 용량 큼 | 대체 글꼴 목록에만 |

적용 방법(권장): npm `pretendard` 패키지의 **가변 글꼴 + 다이내믹 서브셋 CSS**를 번들한다(외부 CDN을 부르지 않아 CSP를 바꿀 필요가 없다). 굵기는 400·600·700·800만 쓴다. 대체 목록: `Pretendard Variable, Pretendard, -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`. 라이선스 파일(OFL.txt)을 배포물에 함께 둔다.

## 4. 지금 우리 화면이 실제 서비스와 달라 보이는 이유

현재 코드(`frontend/src/styles.css`, `App.tsx`, `pages/HomePage.tsx`, `pages/ShowPage.tsx`)와 1단계 관찰을 대조했다. 영향이 큰 순서.

| # | 지금 우리 화면 | 실제 서비스 | 차이가 주는 인상 |
|---|---|---|---|
| 1 | **메인 첫 화면에 배너가 없다.** 장르 탭 + 검색창 줄로 시작해 랭킹과 오픈 예정이 바로 나온다 | 네 곳 모두 첫 화면 절반 이상이 큰 배너 슬라이드(NOL 1240×403, 예스24 전체 폭 650px, 티켓링크 모바일 335×380) | "관리 화면/목록 화면" 같다. 상품을 파는 가게의 진열대가 없다 |
| 2 | **장식용 제목 글꼴**(Black Han Sans)을 로고에 36px로, 본문은 IBM Plex Sans KR | 본문·제목 모두 고딕 1종(Pretendard 계열), 로고만 이미지 | 굵은 붓글씨풍 제목 + 개발자용 고딕 조합이 데모 사이트 인상을 만든다 |
| 3 | **바탕이 회색 종이색**(`#EDEFF2`)이고 카드 면이 따로 있다 | 바탕은 흰색. 회색 면은 공지 띠·필터 상자에만 | 전체가 탁하고, 포스터가 덜 산다 |
| 4 | **행동 색이 리소 블루 `#2F4FD8` + 핑크 `#F0469A` 두 가지**, 등급 색 4개까지 합치면 화면에 색이 많다. 게다가 블루는 NOL의 행동 색(`#4154FF` 근처)과 같은 계열 | 행동 색 1개 + 경고 빨강 1개 | 색이 많아 "디자인 콘셉트"가 앞에 나온다. 또 NOL과 같은 계열 파랑이라 차별도 안 된다 |
| 5 | **머리글에 검색창이 없고 메뉴가 "공연 / 내 예매" 2개**, 높이 64px 한 줄, 아래 2px 진한 선 | 머리글 72px 안에 넓은 검색창 + 계정 아이콘, 그 아래 장르 메뉴 줄(6~10개), 맨 위 보조 링크 줄 | 서비스의 "뼈대"가 얇아 보인다. 장르가 본문 안 탭으로 들어가 있다 |
| 6 | **목록 열 수가 화면 폭에 따라 들쭉날쭉**(`auto-fill, minmax(11.5rem, 1fr)`) | 5열 고정(필터 있으면 4열), 카드 크기 일정 | 격자가 정돈되지 않아 보인다 |
| 7 | **카드에 상태 머리표가 약하다.** 매진·종료만 가격 줄에 글자로 | 포스터 위·아래에 `D-1`, `단독판매`, `좌석우위`, `N차 티켓오픈`, 할인 % 같은 짧은 머리표 | 정보 밀도가 낮고 "급함"이 안 보인다 |
| 8 | **문구가 길다.** "잔여석은 판매된 좌석만 뺀 수입니다. 다른 관객이 지금 고르고 있는 좌석이…" 같은 설명이 화면 곳곳에 | 라벨은 2~6자(장소·기간·관람시간), 설명은 유의사항 목록이나 물음표(ⓘ) 툴팁으로 | 설명문이 많은 화면은 생성된 화면처럼 읽힌다 |
| 9 | **보조 화면이 없다.** 공지·고객센터·FAQ·티켓 오픈 전체·랭킹 전체·장르 화면 | 네 곳 모두 있음. 푸터 위 고객센터 묶음, 푸터 안 정책 링크·회사 정보 | 서비스가 "몇 장짜리"로 보인다 |
| 10 | **푸터가 안내 문장 3줄** | 정책 링크(개인정보처리방침 강조) + 고객센터 연락처·운영시간 + 사업자 정보 + 저작권 | 실제 서비스의 마지막 단서가 빠져 있다 |
| 11 | **상세의 예매 영역이 3단 격자의 한 칸**이고 스크롤하면 사라진다 | NOL: 오른쪽 360px 고정(sticky) 상자, 모바일은 하단 고정 버튼 | 긴 상세를 읽다가 예매로 돌아가기 어렵다 |
| 12 | **상세에 탭이 없다.** 소개·유의사항을 이어 붙임 | 상세정보·캐스팅·가격·취소/환불·공연장·후기 탭(또는 칩) | 정보 구조가 평평하다 |
| 13 | **모바일 하단 탭 막대가 없다** | 티켓링크·NOL·예스24 모두 55~57px 하단 탭 막대 | 앱처럼 쓰는 모바일 웹의 관례에서 벗어난다 |
| 14 | 모서리가 4px·10px 두 종류이고 테두리·그림자 규칙이 화면마다 다름 | NOL: 버튼 16, 칩 완전 둥금, 카드 포스터 8~12. 예스24: 0. 한 서비스 안에서는 일관 | 부품이 서로 다른 출처에서 온 것처럼 보인다 |

정리하면, 기능 부족보다 **"서비스 뼈대(머리글·배너·푸터·보조 화면)와 밀도(머리표·열 수)"가 빠진 것**과 **"콘셉트성 장식(종이 바탕, 장식 글꼴, 두 가지 강조색, 긴 설명문)"이 많은 것**이 시제품 인상의 핵심이다.

## 5. 차별을 위해 지킬 것 (특정 서비스와 같아 보이지 않게)

- 행동 색은 네 곳(파랑·주황/빨강·녹색·빨강 계열)과 겹치지 않는 **청록(teal) 계열**로 새로 정한다(03 문서 3.1).
- 배너 비율은 NOL(약 3.08:1, 둥근 카드)·예스24(전체 폭)와 다르게 **본문 폭 1200 안 3:1, 모서리 12px, 양옆 슬라이드 보이지 않음**으로 한다.
- 메인 섹션 이름은 우리 말로 짓는다("티켓 오픈 예정", "지금 많이 보는 공연", "곧 막을 내려요" 등). 다른 서비스의 섹션 이름(WHAT'S HOT, PICK 등)을 쓰지 않는다.
- 머리표 이름도 우리 데이터에 있는 상태만 쓴다(오픈 예정·D-n·매진 임박·매진·판매 종료·N위). 단독판매·좌석우위처럼 다른 서비스 고유 표시는 쓰지 않는다.
- 로고는 글자 로고(아래 03 문서 3.8). 다른 서비스 로고처럼 영문 대문자 굵은 로고로 만들지 않는다.
